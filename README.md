## About

**Sauce Engine** is an independently developed game engine written completely from scratch in **C++** and **OpenGL**.

The project has been in development for approximately **one year** at the time of this repository's publication.

Sauce Engine is designed around the idea of creating an independent, Source-compatible engine without relying on leaked or stolen Source Engine source code.

The long-term goal is to provide an alternative to the original Source technology while improving its technical limits and expanding what can be achieved by the engine.

The project is currently in active development.

---

## What makes Sauce Engine different?

* Written from scratch
* Source-compatible architecture and content support
* C++ / OpenGL based renderer
* Jolt Physics integration
* Designed with higher engine limits in mind
* Independent implementation without leaked Source Engine source code

## Building

### Requirements

Sauce Engine is currently built for **64-bit Windows** using **MinGW-w64**, **C++17**, and **CMake**.

You will need:

* Windows 10/11 x64
* MinGW-w64 GCC (`g++.exe`)
* C++17 support
* CMake 3.20 or newer
* GNU Make (`mingw32-make.exe`) or Ninja
* Windows system libraries, including OpenGL (`opengl32`)

**GLFW and Jolt Physics are already included in the repository.** You do not need to download or configure them separately.

C++17 support is configured automatically by CMake. OpenGL is linked through the Windows system libraries.

### Installing the build tools

#### MinGW-w64

Install [MSYS2](https://www.msys2.org/).

Open the **MSYS2 UCRT64** terminal and run:

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-make
```

This installs the GCC compiler and Make required to build the engine.

#### CMake

Install CMake from the official website:

https://cmake.org/download/

Make sure the installation includes `cmake.exe`.

Ninja can also be used as an alternative build tool if it is installed and detected by the build script.

### Project structure

The project uses CMake to organize the build and automatically collect the engine's C++ source files.

```text
SauceEngine/
├── CMakeLists.txt
├── build.bat
├── run_as_admin.bat
├── tools/
│   └── build.ps1
│
└── src/
    ├── app.manifest
    ├── app.rc.in
    │
    ├── engine/
    │   ├── app/
    │   │   ├── main.cpp
    │   │   ├── engine_console.cpp
    │   │   └── engine_console.h
    │   │
    │   ├── core/
    │   ├── render/
    │   ├── ui/
    │   ├── entities/
    │   ├── gameplay/
    │   ├── network/
    │   └── physics/
    │
    ├── glfw/
    │   ├── include/
    │   └── lib/
    │
    └── Jolt/
        ├── Core/
        ├── Physics/
        └── lib/
            └── libJolt.a
```

The `build/` directory is generated by CMake during compilation. The final `SauceEngine.exe` is generated in the project root.

The GLFW and Jolt libraries must remain in their existing locations. No manual dependency path configuration is required.

### Building the engine

Run `build.bat` from the project root.

The build script automatically searches for a compatible 64-bit MinGW-w64 compiler, CMake, and a supported build tool. It can search common installation directories and local drives instead of relying exclusively on the system `PATH`.

The script then configures the project with CMake, builds the engine in Release mode, and launches the resulting executable with administrator privileges.

```bat
build.bat
```

To build without automatically launching the engine:

```bat
build.bat --no-run
```

You can also run `build.bat` by double-clicking it or by specifying its full path from another working directory.

The build script includes handling for project paths containing non-ASCII characters, such as Cyrillic directory names.

If CMake or MinGW-w64 cannot be found, the script may offer to install the required tools through `winget`, where available.

After a successful build, the executable will be generated as:

```text
SauceEngine.exe
```

### Build output

After building, the project root will contain:

```text
SauceEngine/
├── SauceEngine.exe
├── CMakeLists.txt
├── build.bat
├── run_as_admin.bat
├── tools/
├── src/
└── build/
```

The `build/` directory contains generated build files and intermediate objects.

## Running

To run a Source game with Sauce Engine, you need a **legally purchased copy of the game** and its required game files.

### Half-Life 2

Place `SauceEngine.exe` in the root directory of your Half-Life 2 installation.

Example:

```text
Half-Life 2/
├── hl2.exe
├── SauceEngine.exe
├── hl2/
├── bin/
├── platform/
└── ...
```

Then launch:

```text
SauceEngine.exe
```

The executable requests administrator privileges when launched.

You can also use `run_as_admin.bat` to launch an already-built executable with administrator privileges.

### Other Source games

For other supported games, place `SauceEngine.exe` in the game's root directory and launch it using the `-game` parameter:

```text
SauceEngine.exe -game <game_name>
```

For example:

```text
SauceEngine.exe -game portal
```

The value passed to `-game` should correspond to the game's directory name.
